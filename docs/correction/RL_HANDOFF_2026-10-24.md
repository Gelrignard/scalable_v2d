# Current correction method and downstream policy handoff

Status checked on 24 October 2026 against source commit `2d4df40` and saved full-episode results. This document describes the implemented staged method; the earlier coupled-horizon and MPC documents describe separate experiments. No policy training or new physical rollout was performed for this documentation audit.

## 1. What we have, and what we have not established

We construct robot contact surfaces, robot motion and force guidance in successive optimization stages. During execution, an optional small force-allocation QP uses actual simulator state. The robot and object then evolve under contact dynamics. The object is never moved by writing the desired trajectory into its state.

This is **staged trajectory/contact optimization with an observed-state force adapter**, not a single successful joint trajectory optimizer, not MPC, and not a learned policy. The force adapter preserves the saved robot motion, phase clock, grasp family and finger shapes. It cannot acquire a missing contact or move the planned grasp to a displaced object.

The bin has a substantially better physical outcome than original retargeting. However, **none of the three current full G1 episode comparisons passes our physical acceptance checks**. The newer observation adapter has not improved on the preserved bin controller and is not promoted as the default. Reduced fingertip-pad successes are separate experiments and do not certify the articulated robot.

It is reasonable to hand these artifacts to a policy developer as experimental references. It is not reasonable to label them clean expert demonstrations or assume RL will fix every failure. No reduction in training steps or GPU-hours has yet been measured. A reference need not be a perfect demonstration to be useful as a soft learning target; that usefulness is precisely what the controlled experiment must test.

## 2. Inputs and coordinate conventions

The correction consumes retargeting output, not RGB video:

- Time-indexed robot configuration, human/contact evidence, and the tier-appropriate object pose observations.
- Actual robot collision geometry and joint limits; object visual mesh and its collision decomposition; registered ground/support geometry.
- Object mass, center of mass, inertia, friction and controller settings. The current transfer trials use prototype defaults, not validated official-simulator parameters.
- Source indices, visibility/provenance and the constant source-to-world transform. Tier 2 requires a new explicit missing-data/uncertainty adapter; it cannot be passed through the Tier 1 loader under a different directory name.

Use the retargeter's saved `metadata_json`, especially `joint_names`, `q_layout`, `source`, and `urdf_sha256`. The actual convention is:

| Quantity | Convention |
|---|---|
| Full robot `q` | Root xyz, root quaternion **xyzw**, then named robot joints; current G1 arrays have 50 columns |
| Object `object_wxyz` | Quaternion **wxyz**, object-local to world rotation |
| Positions / time / joint angles | Metres / seconds / radians; constant world frame with z up |
| Contact force | Robot-on-object force, world coordinates, newtons |
| Wrench | World force followed by world moment about the actual object COM, N and N m |
| `robot_local_points` | Points in the associated robot body frame, not the palm frame by default |
| `object_local_points`, `inward_normals_local` | Object-local points and inward normals |
| Active-joint arrays | Columns selected by `movable_joint_indices`; current supported model has 31 movable arm/hand/waist joints |

Do not copy full `q` into a MuJoCo qpos array or assume it has the learner's joint order. MuJoCo free-joint quaternions use wxyz. The supported model removes/fixes leg joints, so its generalized velocities are not the complete G1 velocity vector either. Map by names and test forward kinematics.

Four different object trajectories must remain distinct:

1. **Observed input** for the requested tier.
2. **Planning reference**, which may be adjusted using permitted observations or local simulation.
3. **Actually simulated outcome**, generated by contact and actuator dynamics.
4. **Official scoring reference**, accessible only through the appropriate evaluation path when it would otherwise leak clean information.

In our Tier 1 comparisons, the original observed and scoring-target poses coincide. The bin's second interaction has a simulation-informed planning translation that decays to zero; scoring poses remain unchanged. This earlier offline adjustment is not online recovery. `staged_planning.py` verifies its ancestry rather than substituting the previous simulated outcome for the target. Desk/stroller planning equals the input poses.

Ground-truth **current simulated state** is different from a clean demonstrated **future trajectory**. Using the former for a training teacher does not justify loading Tier 1 future targets into a Tier 2 corrector. Actor/critic observation permissions still need checking in the chosen policy runtime.

## 3. Offline stages, with the bin as an example

Let the retargeted motion be $\bar q_k$, object pose $(\bar p_k,\bar R_k)$, and human-derived contact evidence $E_k$. The useful human information is a prior on contact regions, hand choice, posture, timing and approach. It is not an exact contact point or measured force.

### A. Select and fit physical contact patches

For candidate robot body $B_i$, choose a point $r_i$ on its collision surface and a point $c_i$ on an object collision surface. Their world locations are

$$
x_i(q)=p_{B_i}(q)+R_{B_i}(q)r_i,
\qquad y_i=p_O+R_Oc_i.
$$

`surface_hypotheses.py` proposes a small set of surface explanations near the observed interaction. `patch_geometry.py` fits upper-body joints and bounded coordinates on the selected collision triangles. Its least-squares terms penalize point mismatch, incompatible contact normals, deviation from the demonstrated posture/region, and unwanted penetration. Joint bounds and triangle coordinates restrict the search. Separate nonlinear geometry gates are checked afterward; a small solver cost alone is insufficient.

For the bin, a proximal finger surface can touch before the originally selected distal point. Explicitly representing that proximal surface changes the contact explanation. Merely applying a larger force at the unreachable distal point does not solve acquisition.

### B. Construct an approach, carry and release motion

An accepted static candidate supplies finger shape and object-relative hand pose. Continuous IK constructs an approach, closure, transport, unloading and release sequence; inactive transitions receive collision/continuity checks. The preserved bin has two declared contact phases plus local repairs. Its timing and second-grasp planning offset are experiment-specific parameters, not outputs of a general automatic phase optimizer.

The newer `transfer_episode.py` chooses candidate frames/families from input evidence before replay, but `episode_phase.single_phase` accepts **exactly one** observed interaction interval with sufficient approach/release time. It does not implement arbitrary multi-grasp episodes, rolling contacts or articulated objects.

### C. Allocate a time-coupled force profile

At fixed robot/object poses, define the grasp operator about COM $c_O$:

$$
G_k=\begin{bmatrix}
I&\cdots&I\\
[x_{1,k}-c_{O,k}]_\times&\cdots&[x_{m,k}-c_{O,k}]_\times
\end{bmatrix}.
$$

The current `actuator_force_profile.py` solves the quasistatic problem

$$
\min_F\sum_k\|S^{-1}(G_kF_k-w_k^{\mathrm{hold}})\|^2
+10^{-5}\|F\|^2+2\cdot10^{-5}\|D_tF\|^2,
\qquad S=\operatorname{diag}(10,10,10,1,1,1).
$$

Here $w^{\mathrm{hold}}=[-mg;0]$, with the phase loading convention recorded in the run. Forces are subject to friction-pyramid, nonnegative normal/preload, normal-force-cap and nominal joint-torque constraints. The current default preload is 2 N, normal cap 15 N and static torque reserve 90% of actuator capacity. Optional environmental force slots come from the collision manifold at the **nominal planning state**; sliding friction must oppose the predicted tangential motion. These are not online measured support states.

Force magnitude, preload, the human-constrained contact geometry and temporal regularization choose among infinitely many wrench-compatible forces. This is where preference enters; wrench balance alone does not select a manipulation.

**This stage does not infer a per-frame inertial wrench by differentiating noisy object observations. It also does not enforce the full dynamic object trajectory.** Its torque constraints omit robot inertia and tracking feedback. A later physical replay must establish what the object actually does.

### D. Refine the robot command with a spline

For upper-body joint coefficients $z$, use cubic B-spline operators:

$$
q_a=Bz,\quad \dot q_a=B_1z,\quad \ddot q_a=B_2z.
$$

`command_smoothing.py` minimizes

$$
\|Bz-q_{a,\mathrm{seed}}\|^2+2\cdot10^{-6}\|B_2z\|^2+10^{-9}\|z\|^2.
$$

Constraints include the initial physical state, joint/velocity bounds, local trust regions, preservation of active contact locations through frozen Jacobians, and a frozen-model nominal torque bound:

$$
\left|M_{aa,k}(B_2z)_k+M_{ar,k}\ddot q_{r,k}
+h_{a,k}-\tau_{\mathrm{passive},k}+J_k^TF_k\right|
\leq0.9\tau_{\max}.
$$

The prescribed pelvis trajectory is $q_r$. Forces and contact identities stay fixed in this stage. Continuous coefficient bounds are an optional conservative check between sample times. Neither the linearized constraints nor command continuity guarantees that actual contact remains stable under saturation.

When a stage fails, the transfer runner normally stops before physical replay. `--replay-rejected` explicitly produces a diagnostic replay of a finite pre-spline candidate. **Such an output must not be described as an optimized or accepted spline.** Both additional transfer episodes use rejected upstream plans.

## 4. What feedback changes during execution

The baseline already evaluates PD error, robot dynamics/Jacobians, object orientation and contact sensing at simulated states. The newer `staged_observation.py` adds an **instantaneous force residual** using the actual object COM pose/twist and matched contacts. It does not replace all nominal states in the offline optimization.

With reference COM errors $e_p,e_v$, orientation error $e_R=\log(R_{\mathrm{plan}}R_{\mathrm{sim}}^T)$ and angular-velocity error $e_\omega$, its default target increment is

$$
\Delta w_{\mathrm{goal}}=
\begin{bmatrix}
\operatorname{clip}_{3\,\mathrm N}\{m(8e_p+3e_v)\}\\
\operatorname{clip}_{0.15\,\mathrm{N\,m}}\{I_W(12e_R+3e_\omega)\}
\end{bmatrix}.
$$

The clips bound vector norms. Reference translation is smoothed; reference twist comes from the reference curve/rotation secant. No observed object acceleration is differentiated. Actual robot kinematics are refreshed separately, while contact sensing uses the latest solved physics step.

For matched physical contact points only, construct $G_{\mathrm{sim}}$ and solve

$$
\min_{\Delta f}\|D^{-1}(G_{\mathrm{sim}}\Delta f-\Delta w_{\mathrm{goal}})\|^2
+0.1\|\Delta f\|^2,
\qquad D=\operatorname{diag}(3,3,3,0.15,0.15,0.15).
$$

Constraints bound increments by 0.75 N per component, intended change rate by 10 N/s, actual-normal friction/preload, and additional torque near joint limits. The instantaneous torque envelope is

$$
|\tau_0+J_{\mathrm{sim}}^T\Delta f|
\leq\max(\tau_{\max},|\tau_0|),
$$

where $\tau_0$ is the complete nominal PD/compensation/force-guidance torque request. Thus an inherited overload may persist but may not worsen at that instant. This is **not** a feasibility certificate. Actual torques remain clipped at the physical limits.

If changing constraints conflict with the rate bound, the current solver retries without that bound, logs the discontinuity and rejects acceptance. There are 16 such events in the latest bin replay and 63 in the stroller. Zero matches imply zero additional allocated object wrench; absence of a selected match does not mean there are no contacts anywhere on the robot.

For example, if the grasped bin is slightly below its planning path, the observed error asks for a bounded upward wrench correction through the contacts that actually exist. If the hands have missed it entirely, this QP cannot pull the bin toward them and does not change the hand path to find it.

The actuator request is conceptually

$$
\tau_{\mathrm{req}}=K_p(q_{\mathrm{cmd}}-q_{\mathrm{sim}})
+K_d(\dot q_{\mathrm{cmd}}-\dot q_{\mathrm{sim}})
+\tau_{\mathrm{comp}}+\tau_{\mathrm{contact,base}}+J_{\mathrm{sim}}^T\Delta f.
$$

The simulator determines realized contact forces. Guidance is never injected directly into the object. Calling this a delta-force adapter is accurate; calling its robot commands a delta-position policy is not. That policy interface is still a downstream choice.

The bin remains a useful reference experiment. Desk feedback is exactly zero because none of 16,900 force updates finds a matched selected patch. Stroller has no match on 21,675 of 26,967 updates. Neither validates generalization. The bin's manual phase/repair history also means the table is not an unbiased automatic-method benchmark.

All three profiles specify object mass 1 kg, local COM zero, diagonal inertia $(0.01,0.01,0.01)$ kg m², physics friction 1.0 and a 1 ms physics step. The planner/controller uses friction 0.8. These values are reproducible prototype settings, not identified object properties. The stroller is a single rigid object without articulated wheels; the registered environment and convex collision pieces retain known approximation errors.

Requested torque peaks in the latest bin/desk/stroller are 2.27 / 160.78 / 21.96 times capacity; applied torques are clipped. The bin has a 9.57 mrad joint-limit excursion, below the current local 10 mrad tolerance; its rejection includes tracking, requested torque and residual-rate failures. Desk/stroller also exceed the joint-limit tolerance. These violations are not hidden by successful numerical QPs.

The local physical gate requires maximum position error below 10 mm, maximum rotation error below 5 deg, penetration below 1 mm, initial penetration below 0.05 mm, joint-limit excursion below 0.01 rad, no direct object force, and requested torque within capacity. The observed adapter adds its solver/rate gates and inherited planning acceptance. These development thresholds are not official scoring thresholds and do not constitute a complete whole-body safety certificate.

Observed-adapter replays took 248.45 / 307.72 / 470.72 seconds wall time for bin/desk/stroller, with roughly 0.94–1.14 GB peak process RAM and no GPU. These timings exclude upstream decoding, candidate search, retargeting and spline optimization; desk/stroller ran concurrently. They do not establish end-to-end batch cost. The implementation currently runs avoidable zero-authority QPs.

There is **no complete bulk training-bundle exporter** for this staged method. The following are existing research artifacts, verified against the saved bin arrays. Let T be frames, C contact channels, J all joints, and A active supported-model joints; here T=858, C=6, J=43, A=31. Shapes may differ for other candidates.

| `mechanics.npz`: `robot_contact_wrench_world`, `environment_contact_wrench_world`, `interval_*impulse*` | All-robot vs environment effects and integrated impulses; use interval quantities to avoid missing impacts between video frames. |
| `mechanics.npz`: `movable_joint_indices`, `torque_caps`, `frame_peak_*`, `staged_observation_*` | Joint mapping, physical limits, dense-step peak audits and feedback diagnostics. |

`mechanics.npz` is video-rate recording plus interval/peak summaries, **not** a complete 1 kHz transition buffer. Do not train a high-rate world model by treating sparse samples as if every action and transition were logged.

An RL adapter must additionally package a versioned manifest with tier, episode/sequence ID, source revision/hashes, joint/body names, frame transform, physics/control period, asset hashes, object parameters, support geometry, planning/scoring distinction, mask definitions, stage statuses and relative asset paths. Some current reports have `episode: null` and rely on ancestry/catalog metadata. Resolve these explicitly. Do not map a missing acceptance field to `true`.

The existing [motion_v1 exporter](../../retargeting/src/v2d_retarget/output/motion_v1.py) needs upstream demo metadata and rejects canonical inputs without it. It recomputes link/finger frames but does not export the staged force-feedback teacher. The older `controller_reference.py` exports a different coupled-solver contract; its presence does not mean this newer pipeline is already integrated into CHORD.

## 7. Recommended downstream learning contract

First establish one official-runtime baseline, then import an experimental reference and measure it. Do not require all our strict development gates to pass before doing any RL research, but make imperfect-reference use explicit.

1. **Action contract:** choose the actual training runtime's supported interface. Our current teacher uses joint torque guidance. If the policy outputs joint position targets, preserve task/force information in goals or rewards, or implement a tested controller adapter. Copying physical joint poses alone discards intended preload. A local position-equilibrium conversion exists but clipping and contact changes can invalidate its torque equivalence. Do not add the same contact torque twice.
2. **Reference contract:** retain desired object motion and confidence-weighted robot/contact targets. Treat planned forces as optional soft guidance, not guaranteed expert actions. Failed physical rollouts may provide dynamics transitions or failure examples, but not positive imitation labels for successful manipulation.
3. **Observations:** separate what the actor sees from privileged teacher/critic inputs. Current simulator pose, twist, joint state and contact are available to this local teacher; deployment/noisy-observation compatibility has not been demonstrated.
4. **Control continuity:** a bounded residual or delta-action interface is a useful option. Specify whether it increments a previous command or offsets a reference, include controller memory in the observation/state when necessary, and bound both magnitude and rate. Delta actions alone do not fix contact acquisition or guarantee smooth realized motion.
5. **Whole-body bridge:** reproduce model, collision, actuator and timing semantics, then test the reference with the intended whole-body controller. The current recorded pelvis fixture is a diagnostic aid. SONIC compatibility and hand/object interaction under its control have not been established.

Use an ablation with the same learner, physics, observations, action interface, seeds, evaluation and budget:

| Variant | Changes |
|---|---|
| A | Original contact-aware retargeting reference |
| B | Staged corrected motion/contact/force guidance |
| C | B plus observed-state guidance, only if it can be implemented under the same declared runtime contract |

Separate motion-only correction from additional force rewards/teacher control if necessary; otherwise B vs A measures the combined system rather than motion quality alone. The NVIDIA baseline can be a separate reference run. Preserve failure counts and unsupported episodes in the denominator.

Report task score vs environment steps, wall time, GPU-hours, peak VRAM, and total preprocessing/training/evaluation cost. Prespecify a target official score and compare time-to-target; report runs that never reach it. A policy may be per episode, per task or shared; the current corrector itself produces per-episode references and does not decide policy architecture. There is no need to assume 60 independent policies solely because there are 60 tier/episode inputs.

## 8. SuperMimic: where to borrow ideas

[SuperMimic](https://arxiv.org/pdf/2610.28480), Sections 3 and 6, alternates simulator data collection, fitting a differentiable world model, and policy improvement by differentiating short imagined rollouts with a terminal critic. It explicitly does not yet handle object interaction or terrain. Its policy uses normalized joint setpoints. Therefore this is chiefly a policy-learning direction for us, rather than an existing replacement contact optimizer.

The [authors' project page](https://supermimic.github.io/) reports three hours on an H100 to surpass a released SONIC checkpoint, with different training-data volumes and hardware. This is not a prediction of three hours on our 24 GB RTX 4090, nor a demonstrated V2D manipulation speedup. We have not verified an installable training release or memory fit.

**Our proposed extension, not an implemented or demonstrated result:** use the staged method to supply interpretable goals and candidate interaction regions, while fitting a shared transition model from the learner's actual robot-object simulator transitions:

$$
\hat s_{t+1}=f_\theta(s_t,a_t;\xi),\qquad
s_t=(q,\dot q,p_O,R_O,v_O,\omega_O,h_t).
$$

Here $h_t$ includes required controller history; $\xi$ specifies geometry, object/robot physical parameters and support context. A reduced model can also use relative contact geometry, but it must represent contact loss and object response, not only robot motion. Sharing only across motions with identical robot and compatible object dynamics is the first tractable experiment; generalizing across new shapes requires additional conditioning and validation.

Train the policy against an object-task objective plus soft motion/contact priors, for example

$$
r_t=-\ell_O(T_{O,t},T_{O,t}^{\mathrm{goal}})
-\alpha m_t^q\ell_q(q_t,q_t^{\mathrm{ref}})
-\beta\sum_i m_{i,t}^f\ell_f(f_{i,t}^{\mathrm{meas}},f_{i,t}^{\mathrm{guide}})
-\gamma\|a_t-a_{t-1}\|^2-\ell_{\mathrm{limits}}.
$$

This is a proposed template, not tuned weights. Masks/confidences must not reward force exerted through a nonexistent contact. Task progress and contact acquisition must remain possible even when the demonstration's contact timing is wrong. A failed guide should be downweighted or excluded from imitation, not copied harder.

Our staged optimizer and such a learner would address different costs: the optimizer makes a useful reference cheaply; the shared world model could amortize learning dynamics across references. Keep an ordinary simulator-trained baseline so improvements can be attributed to each contribution. Test the model on held-out **physical simulator** transitions, especially first touch, slip, release and saturation. Recollect data around model failures; do not claim success based on imagined rollouts. Backpropagating through a learned contact model can exploit erroneous gradients even when average prediction error looks small.

This would be model-based policy learning, not a return to our unsuccessful online MPC implementation. Do not make it a prerequisite for the first reference-quality ablation. It is a subsequent experiment once the official-runtime input/action contract works.

## 9. Tier 1/2 batch readiness and minimum next work

**Ready now:** a downstream developer can inspect the preserved bin, import its experimental reference, reproduce diagnostics, and build/evaluate a baseline learner. The method and existing arrays are sufficiently concrete for integration work.

**Not ready now:** an unattended all-episode Tier 1+2 run producing a clean, portable training dataset. A batch wrapper alone would encounter unsupported phase sequences, missing Tier 2 handling and incomplete exporter/physics contracts.

| Requirement | Current state | Work needed before claiming batch handoff |
|---|---|---|
| Complete tier-aware inputs | Tier 1 fetch/decode only; decoder selects one contiguous visible object segment | Explicit Tier 2 decoder, visibility/confidence masks, source indices, uncertainty treatment and no clean-reference leakage |
| Phase/contact coverage | Special two-phase bin; generic transfer restricted to one interval | Automatic multi-interval support, or explicit unsupported status per episode without silent cropping |
| Object/environment models | Convex decomposition; prototype mass/inertia; stroller rigid; registration limitations | Match official assets/physics and explicitly model or flag unsupported interactions |
| Motion/force validity | Useful bin candidate; two failed transfers; optional feedback not promoted | Separate planning, physical execution and learning-use status; preserve baseline and reasons for rejection |
| Portable training export | Research NPZs with ancestry and absolute paths; no integrated staged exporter | Named joint/body mapping, self-contained manifest and asset references, resampling, force/reward/controller adapter |
| Policy/evaluation | `training/` is a scaffold on main; inspected local Tier 2 worktree also has no trainer | One baseline and one corrected-reference run in the official runtime; valid evaluation artifact |
| Scaling claim | Three CPU feedback replay timings, no RL learning curves | Paired time-to-score study including preprocessing and failures |

Recommended order: (1) implement the input/export contract and one Tier 1 integration case; (2) make the same episode work from genuinely noisy Tier 2 input; (3) run the prescribed small pilot, retaining failed cases; (4) freeze configuration and batch every tier/episode to a manifest of accepted, experimental, unsupported or failed outputs. Those status labels are a proposed export contract, not currently implemented fields. Whole-body policy integration can proceed in parallel with correction generalization, but neither should conceal the other's failure modes.

The [official FAQ](https://nvidia-isaac.github.io/video_to_data/v2d_challenge/assets/v2d_challenge_2026_faqs.pdf) requires learned-policy object trajectories for all 30 references per tier and whole-body control; pretrained controllers are permitted. The [challenge page](https://nvidia-isaac.github.io/video_to_data/v2d_challenge/) requires separate submissions for all three tiers, scored against clean object trajectories, and lists a 4 November 2026, 5 p.m. EST freeze. Tier 1+2 artifacts are therefore an intermediate deliverable. Corrected NPZs or code alone are not the leaderboard submission.

## 10. Reproduction entry points and handoff checklist

Existing commands, from the repository root in the documented CPU environment, with fresh output directories:

```powershell
python -m correction.scripts.replay_staged_observation --source correction/outputs/overnight_20261020/rest_matched_v1 --planning-sequence correction/outputs/overnight_20261020/proximal_sequence_v1 --output correction/outputs/my_bin_feedback --gain 1

python -m correction.scripts.transfer_episode --source <prepared-full-episode-directory> --output correction/outputs/my_transfer

python -m correction.scripts.replay_staged_observation --source <completed-transfer-directory> --output correction/outputs/my_transfer_feedback --gain 1
```

`transfer_episode` requires an existing prepared episode bundle; it is not a dataset loader. Its last replay command is applicable only if planning passed or diagnostic replay was explicitly requested and recorded. Gain zero is the nominal-equivalence regression, not a new correction. These entry points were inspected for this document, not rerun.

Before a downstream run, record source commit and dirty-tree state, dataset revision/tier/episode, reference hashes, model/controller version, exact gains, transforms, timing, masks and selected variant. Keep original, intended, planning and actual trajectories separate. Save the complete uninterrupted evaluation; training curriculum resets, if used, must not masquerade as full-episode execution.
